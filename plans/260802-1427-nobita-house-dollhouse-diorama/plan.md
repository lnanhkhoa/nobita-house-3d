# Nobita's House 3D Dollhouse Diorama

## Overview

Single-page WebGL dollhouse of Nobita's house. Orbit the diorama, strip the roof and 2nd floor, auto-cut walls facing camera, jump to any of 11 rooms, click a hotspot pin → camera flies in and an info card opens. Low-poly stylized, English UI, local dev only.

Assets are generated by hand in the Hyper3D Rodin web UI, one prop at a time. The app must never block on missing assets: **every prop with no GLB renders as a palette-coloured proxy box**, so the full scene is walkable and testable from day one and each downloaded GLB silently upgrades it.

## Stated assumption (not user-confirmed)

The user chose "auto-generated box proxies" for props but did not rule on the **house shell** (floors, walls, roof, stairs, yard). This plan builds the shell **procedurally from `rooms.ts`**, not from Rodin, because the dollhouse features structurally require it: roof toggle, per-floor toggle, and camera-facing wall cutaway all need individually addressable, code-owned wall meshes with known normals. A single monolithic Rodin mesh cannot be cut away per-wall. A hand-made shell GLB can still replace it later without touching the controller. **If this is wrong, say so before Phase 3.**

## Type contract (`src/data/types.ts` — single source of truth)

```ts
export type FloorId = 'ground' | 'second';

export interface RoomDef {
  id: string;                  // kebab-case, unique
  name: string;                // English
  kana?: string;               // JP decoration only
  floor: FloorId;
  jo?: number;                 // tatami count (canon sizing)
  footprint: { x: number; z: number; w: number; d: number };  // metres; origin = house NW corner. Frame: +X east, +Y up, +Z south
  height: number;              // ceiling height, metres
  walls: WallSpec[];           // per-edge: solid | opening | none — drives shell + cutaway
}

export interface PropDef {
  id: string;                  // kebab-case; must match public/models/<id>.glb
  name: string;
  roomId: RoomDef['id'];
  size: [number, number, number];   // approx bbox metres — drives the proxy box AND sanity-checks real GLBs
  rodinPrompt: string;              // kept in-repo so assets are reproducible
  hotspot?: string;                 // HotspotDef.id
}

export interface AssetMeta {        // per-asset correction — Rodin does NOT centre pivots
  scale?: number;
  offset?: [number, number, number];
  rotation?: [number, number, number];   // radians
}

export interface HotspotDef {
  id: string;
  propId: PropDef['id'];
  title: string;
  body: string;                     // 2-4 sentences
  anchor?: [number, number, number];// pin offset in prop-local space
}

export interface LayoutEntry {      // authored by editor mode → public/layout.json
  propId: PropDef['id'];
  position: [number, number, number];
  rotationY: number;
  scale: number;
}
```

## Reconciled contracts (post-planning amendments)

Phases 01-04 and 05-09 were written in parallel and surfaced genuine conflicts with each other. Resolved below. **These override anything above and any phase file that still disagrees.**

| # | Conflict | Resolution |
|---|---|---|
| 1 | Coordinate origin — this file said SW, Phase 2 derived NW | **NW.** In a right-handed +X-east/+Y-up frame, +Z is necessarily south, so min-X/min-Z is the NW corner. Phase 2 is correct; fixed inline above. `FLOOR_Y = { ground: 0, second: 2.55 }`. |
| 2 | Wall `userData` names — Phase 3 emits `floor`/`outward`, Phase 5 consumed `floorId`/`outwardNormal` | **Producer wins.** Canonical: `{ kind:'wall', roomId, floor: FloorId, side, outward: readonly [x,y,z] unit, exterior, wallKey }`. Mesh position *is* the wall centre. Phase 5 corrected to these names. |
| 3 | Exterior wall materials — Phase 3 specified one shared material + `visible=false`; Phase 5's fade needs per-wall opacity | **Per-wall material instances, exterior walls only.** Exterior walls are already individual meshes, so cloning their material costs **zero** extra draw calls — a draw call is per mesh/material pair and each wall is already its own mesh. Interior partitions stay merged with a shared material. Phase 5's 180ms fade is affordable; Phase 3 corrected. |
| 4 | `< 50` draw calls is unreachable (shell 32 + ~63 prop objects ≈ 95) — **escalated independently by both agents** | **Budget raised to `< 120` draw calls.** The `< 50` figure came from a generic best-practices article, not from this scene's composition; ~100 draw calls of trivial low-poly geometry is not a real constraint on a modern mobile GPU. The `< 80k` triangle budget is unchanged and remains the meaningful gate. `BatchedMesh`/`InstancedMesh` stay *documented* Phase 9 escape hatches, triggered by **measured frame time**, never by a draw-call count. Do not build them pre-emptively — both agents were right to refuse. |
| 5 | "65 props" is not the loadable count | `PROPS.length === 65`, but 11 rows are shell geometry (`builtBy:'shell'`) → **`PLACEABLE_PROPS.length === 54`**; placed object count (with `count`) = 63. Every UI count (loading veil, editor list) reads the array, never a literal. |
| 6 | Phases 5-9 require `onChange(key,cb)`, `autoRotate`, `loading:{loaded,total,done}` | Granted; added to Phase 1's `app-state`. `set()` still fires **one** batched `StateChange {prev,next,changed[]}`; `onChange(key,cb)` is a thin filter over that, not a second channel. |
| 7 | `world/materials.ts` absent from the module contract | Added above. Shared memoised palette materials; both Phase 3 and Phase 4 need it. |
| 8 | Room-level hotspots have no `propId` | Phase 2 solves the *data* side via `HotspotDef.anchorWorld`. ~~No second code path in Phase 6.~~ **Corrected by red-team (H4):** that was wrong — Phase 6 resolves pin anchors through `prop-registry`, and a `builtBy:'shell'` prop is not in the registry, so `hs-roof` and its peers resolve to nothing. Phase 6 **must** carry an explicit `anchorWorld` branch. |
| 9 | Phase 5 dropped `fitToBox`; Phase 6 dropped raycast proxy meshes; Phase 8 is desktop-only | **All three accepted** — each is better reasoned than the brief it replaced. `fitToBox` preserves the *current* azimuth, which is exactly the camera-inside-a-wall failure the acceptance criterion forbids; DOM pin buttons already own hit-testing incl. touch, so proxy meshes would only duplicate it; and you cannot place props on a phone. |

Additive type fields from Phases 2/4 (all optional): `RoomDef.outdoor`, `PropDef.count`, `PropDef.builtBy`, `PropDef.asset`, `HotspotDef.anchorWorld`, `LayoutEntry.instance`.
`WallSpec = { side, kind: 'solid'|'opening'|'none', openings?: {u0,u1,v0,v1}[], exterior? }` — openings normalised 0-1, not metres.

**Verified during reconciliation:** `TransformControls` in three 0.185.1 extends `Controls` and exposes `getHelper()` — Phase 8 must add `controls.getHelper()` to the scene, not the controls object.
**Now verified (red-team, from source):** `camera-controls@3.1.2` **does** keep animating a transition while `enabled === false` — `update(delta)` has no `_enabled` guard and `cancel()` only clears user-drag state. Input-lockout during fly-to is safe. Phase 5's smoke check for this is redundant.

## Red-team rulings (second review pass)

An adversarial review verified the plan empirically — it installed `@gltf-transform/cli@4.4.2` to check the flags, read `camera-controls` source, and recomputed both floor tessellations. Findings and my adjudication:

**Confirmed sound, do not re-open:** Phase 4's CLI claims are correct (`weld` genuinely has no options, `inspect --format` genuinely has no JSON — the hand-rolled GLB header parser is justified). Both tessellations tile exactly with zero overlap or gap, all dimensions integer multiples of u = 0.91 m, and `2f-nobita` sits exactly over `gf-living`. All pinned versions exist.

| Ruling | Decision |
|---|---|
| **B1 — wall dedup drops walls** (Phase 3's "room owns its north+west walls" rule vs Phase 2's authored `WallSpec`; living↔corridor and living↔guest walls get built **zero** times, and both T9 and SC-7 pass anyway) | **Rebuild the algorithm edge-first, not room-first.** Collect the set of unique edges across all rooms; build one wall per edge where *any* adjacent room declares `solid`/`opening`. This removes the ownership tiebreak entirely, so it cannot silently drop a wall. Add a test asserting wall count equals unique declared edges. |
| **B2 — exporter drops `LayoutEntry.instance`** (13 objects from `count>1` props collapse onto `#0` on reload; the round-trip test structurally cannot catch it) | Exporter must write `instance`. Round-trip test must use a fixture containing at least one `count>1` prop and assert object **count** as well as positions. |
| **H1 — `roomAzimuth` argmax picks the direction with *more* house in the way** | Invert the metric: pick the exterior-facing direction with the *least* occluding geometry between camera and room centre. |
| **H2 — `houseBox` includes the 13.65 m yard**, making the clamp and the "≥45% fill" criteria mutually unsatisfiable | Two boxes: `lotBox` (incl. `outdoor` rooms) for the whole-house view; `houseBox` (buildings only) for clamping and room framing. |
| **H3 — nobody hides 2F *props* on floor toggle** | `structure-controller` must filter props by floor too, not just shell groups. |
| **H5 — `config.ts` `CAMERA` exported twice** (TS2451) with conflicting `maxDistance` | Phase 1 owns and exports `CAMERA`; `maxDistance = 42` (needed to frame the whole lot). Phase 5 imports it and may add `CUTAWAY` only. |
| **H6 — literal `65` in Phases 7/8/9** | Violates Reconciled #5. Read `PLACEABLE_PROPS.length`. |
| **Floor plan vs reference art** | Red-team is right that `gf-stairs`/`gf-bath` reaching the north wall contradicts `house-ground.webp`, which puts 厨房 there. Adopt `gf-kitchen = A1+B1`, `gf-stairs = B2–B3` — still tiles to 59.6232 exactly. |
| **Cut as gold-plating** | `check-contrast.mjs` (axe already covers it), `texture-budget.mjs` (fold into `build-assets.mjs`), the 2-sample occlusion confirm, and redo (keep undo). **Keep** the 4-state fade machine — `depthWrite:false` during fade is load-bearing, not decoration. |
| **Missing entirely: WebGL context loss** | No phase owned it. Phase 1 adds `webglcontextlost`/`webglcontextrestored` handling. |

Remaining MEDIUM findings (tessellation constant `29.8116` not `29.7916`, 19 exterior walls not 16, stairwell void, roof slit over the genkan, aspect-ratio double-correction in `framePose`, `focalOffset` px-vs-world, Phase 8 specifying ESLint in a Biome project, duplicate token CSS, genkan step not fitting 1.82 m) are all applied in the phase files.

## Risks

| Risk | Mitigation |
|---|---|
| 65 hand-made Rodin assets is a long, manual grind — motivation/consistency decay | Proxy-first architecture means the project is *always* shippable; props are pure upside. Rodin prompts committed in `props.ts` for reproducibility. |
| Rodin exports arrive uncentred / misoriented / mis-scaled | `AssetMeta` correction layer is mandatory from Phase 4, not retrofitted. Editor mode surfaces the corrected transform for eyeballing. |
| Style drift across 65 separately-generated assets | Fixed 8-colour palette + text-to-3D w/ a shared prompt suffix; post-import material override to palette colours where a prop clashes. |
| Procedural shell looks crude next to detailed props | Shell is deliberately flat-shaded low-poly — matches art direction rather than fighting it. |
| Editor mode code leaking into prod bundle | `editor/` reached only via dynamic `import()` behind the `?edit=1` check; Phase 9 asserts it is absent from the prod chunk graph. |
